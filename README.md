# Panda Torrent

Быстрый торрент-клиент для Windows с библиотекой в стиле Steam, интеграцией
RuTracker и слежением за обновлениями раздач.

Стек: **Tauri 2 + Rust** (бэкенд, движок [librqbit](https://crates.io/crates/librqbit))
и **React + TypeScript** (интерфейс в системном WebView2).

## Возможности

- **Торрент-движок** — DHT, PEX, uTP + TCP, LSD, UPnP, magnet-ссылки,
  выборочная загрузка файлов, ограничения скорости, сессия переживает перезапуск.
- **RuTracker** — вход на странице самого трекера во встроенном браузере
  (Cloudflare пропускает только настоящий браузерный движок), поиск с сортировкой
  и пагинацией, **каталог разделов для просмотра без запроса**, **два вида выдачи —
  список и сетка с превью**, скачивание `.torrent` в один клик, зеркала и
  диагностика связи.
- **Библиотека** — карточки с обложками, кнопка «Играть», автопоиск `.exe`,
  избранное, а также список «Посмотреть позже» для того, что отложено кнопкой «+»
  и ещё не скачано.
- **Просмотр во время скачивания** — фильм открывается во встроенном mpv и играет,
  не дожидаясь конца загрузки; перемотка тянет нужные куски.
- **Обновления раздач** — фоновая проверка перезаливов; когда раздача обновилась,
  появляется окно «Раздача обновилась» с разницей в размере. При согласии
  докачивается только разница — то, что уже есть на диске, переиспользуется.

## Требования

- Windows 10/11, WebView2 (входит в состав системы)
- Для сборки: Rust 1.85+, Node 20+, MSVC Build Tools, Windows SDK

### Почему запросы идут через встроенный браузер

RuTracker закрыт джаваскрипт-челленджем Cloudflare. Проверено на живом сайте:
`index.php` отдаёт 200, а `login.php`, `tracker.php`, `viewtopic.php` и `dl.php`
отвечают обычному HTTP-клиенту `403 Just a moment...`. Куки с главной страницы
ничего не открывают, так что обхода на уровне HTTP-клиента нет.

Поэтому все запросы к форуму выполняет скрытое окно WebView2, припаркованное на
origin трекера: Chromium сам проходит челлендж при первой навигации и получает
`cf_clearance`, после чего каждый `fetch()` с этой страницы несёт нужные куки и
настоящий TLS-отпечаток. Результат возвращается в Rust по Tauri IPC. Окно
поднимается по требованию и закрывается после 3 минут простоя.

**Безопасность.** Окну трекера выдан IPC-доступ, поэтому в проекте объявлен
собственный ACL (`src-tauri/permissions/app.toml`). Без него Tauri разрешает
удалённой странице вызывать *любую* команду приложения, включая запуск `.exe`.
С ним worker-окно может вызвать ровно две команды-репортёра, а весь остальной
API доступен только локальному окну.

### Каталог и превью

Каталог берётся с двух страниц, и обе читаются **без входа**: `index.php` даёт
именованные группы разделов, `index.php?c=N` — форумы внутри категории. Id форума
оттуда подставляется в `tracker.php?f[]=N` — тот же эндпоинт, что и у поиска,
поэтому просмотр раздела это просто поиск без слов, с общим парсером выдачи.
Списки кешируются на неделю. Разметка обеих страниц зафиксирована в
`src-tauri/tests/fixtures/` и проверяется тестами.

Тема раздачи открывается структурно: описание с сохранёнными переносами,
скриншоты галереей с увеличением по клику, спойлеры остаются свёрнутыми как на
сайте, комментарии — на отдельной вкладке.

Превью в сетке в выдаче не приходят — картинка лежит только на странице темы.
Поэтому обложка запрашивается лениво: карточка просит её, лишь когда попадает в
зону видимости, одновременно выполняется не больше двух запросов, а ответ —
включая «картинки нет» — кешируется в SQLite навсегда. Первый проход по новой
выдаче заполняется постепенно.

### Просмотр во время скачивания

Файл отдаётся локальным HTTP-сервером на `127.0.0.1` поверх `FileStream` из
librqbit: чтение ждёт недостающие куски, а перемотка через заголовок `Range`
направляет движок к нужной позиции. Порт выбирает система, каждый URL несёт
случайный токен — наружу и другим локальным программам поток не виден.

Играет **mpv**, а не встроенный видеоэлемент: WebView2 умеет только H.264/AAC и
VP9/AV1, тогда как на трекере почти всё — MKV с HEVC и AC3/DTS.

mpv работает **в собственном окне**, а не встроенным в наше. Сначала было
наоборот — окно Tauri отдавалось mpv через опцию `wid`, — и это оказалось
ошибкой: фокус клавиатуры остаётся у окна-хозяина, встроенная панель OSC не
получает событий, и в результате нет ни паузы, ни перемотки. В своём окне всё
это работает сразу: пауза, перемотка, громкость, полный экран, горячие клавиши.

libmpv загружается **в рантайме** через `libloading`, поэтому сборка не требует
SDK, а отсутствие DLL даёт понятное сообщение вместо падения.

### Просмотр без скачивания

Кнопка ▶ на карточке в поиске открывает фильм, ничего не добавляя в библиотеку:
раздача кладётся во временную папку и сужается до одного видеофайла (иначе
тянулся бы весь релиз целиком). Через 5 минут после закрытия плеера фоновая
задача удаляет её; кеш также стирается при запуске приложения.

Настройки плеера переводятся в опции mpv: выравнивание громкости
(`dynaudnorm`/`loudnorm`), громкость, аппаратное декодирование, приоритет языков
дорожек и субтитров, плюс произвольные `name=value`.

```bash
npm run fetch:mpv   # скачивает официальную сборку libmpv (~31 МБ архив)
```

DLL кладётся в `src-tauri/resources/mpv/` и попадает в установщик; в git она не
коммитится. Установщик из-за неё вырастает примерно с 14 МБ до ~45 МБ.

### Как определяется обновление раздачи

При перезаливе тема сохраняет `topic_id`, но у торрента меняется `info_hash`
и растёт `reg_time`. Проверка идёт двумя путями:

1. **JSON-API** `api.rutracker.cc` — без входа и без челленджа, до 100 тем за
   запрос. **Сейчас трекер держит его выключенным**: любой метод отвечает
   `{"error":{"code":1,"text":"Temporarily disabled"}}`.
2. **Страницы тем** — резервный путь. С каждой берётся `#tor-hash`; смены хеша
   достаточно, чтобы считать раздачу обновлённой. Медленнее и требует входа,
   поэтому за проход проверяется до 40 тем, начиная с самых давно не
   проверявшихся.

При применении обновления старый торрент убирается из сессии **без удаления
файлов**, новый добавляется в ту же папку с `overwrite: true`, поэтому
неизменившиеся куски берутся с диска. Карточка библиотеки (обложка, выбранный
`.exe`, избранное) переносится на новый хеш в одной транзакции.

## Безопасность и приватность

- **Приложение никогда не видит пароль.** Вход происходит на странице самого
  трекера во встроенном окне браузера; сессия живёт в куках WebView2 и переживает
  перезапуск. В `config.json` кешируется только отображаемое имя пользователя.
- Прокси из настроек применяется к JSON-API трекера и загрузке обложек. Окно
  браузера ходит через системный прокси Windows, обмен с пирами — напрямую.

## Что проверено, а что нет

**Проверено на живом трекере.** Транспорт работает end-to-end: WebView2 проходит
челлендж на `tracker.php`, `fetch()` из страницы возвращает 104 КБ настоящего
HTML, IPC с чужого origin доходит до Rust. В настройках есть кнопка
«Проверить связь с трекером», которая повторяет эту проверку в один клик.

**Не проверено — нужен вход.** Парсеры выдачи поиска (`search.rs`) и страницы
темы (`topic.rs`, включая спойлеры и комментарии) сверялись с синтетической
разметкой, а не с реальными страницами: они закрыты логином. Каталог разделов,
наоборот, проверен на живых страницах — они открыты без входа. Селекторы написаны защитно (запасные варианты,
приоритет у `data-ts_text`), но после первого входа стоит прогнать поиск и, если
что-то съехало, поправить селекторы — рядом лежат юнит-тесты с фикстурами.
